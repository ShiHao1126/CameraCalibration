# 实施说明

## 状态与范围

已经实现手动示教记录、几何覆盖选点、正/反向关节路径回放、静止 RGB burst 采集、两阶段基线、像素联合求解、IPPE 多初值、退化/歧义检查和独立留出验证。现场已验证状态读取与 RGB 采图。2026-11-19 首次真实回放在首个采样点因原始 dq 噪声误判停稳而超时，未完成任何采样点；同时发现中间路点逐点停车造成反复启停。两处软件逻辑已修改，随后已完成 50 个姿态、每点 10 帧的真实采集。本轮仅离线处理已有数据，不驱动设备。

`archive/project-plan-20261118.json` 保存前期研究设计快照，其中的状态和变量名不是当前实现的说明。边缘定位和内部点混合求解已接入默认流程；机器人运动学误差联合修正、自动 next-best-view、深度偏差标定仍未实现。

## 核心模型

角点前端采用已核对的 r3kit `95ce4caf` 流程：灰度图、APRILTAG 检测、5×5 cornerSubPix。早期实现仅用 SUBPIX，未完成真实带框标记的对照验证，造成轮廓/角点选择回归；该前端已恢复，保留三个原始失败图作为回归样例。此前只换为 APRILTAG 的试验不等于完整复现 r3kit 角点流程。后端仍为下述共享 X/Y 联合优化。

令 `G_i=T_W_E,i` 是采样窗口内实际法兰反馈，`X=T_W_C`，`Y=T_E_M`。几何关系是 `G_i Y=X C_i`。原始角点预测是 `project(K,D,X^-1 G_i Y P_j)`。历史 `joint` 只优化 X/Y 共 12 个自由度；默认 `hybrid` 再优化共享径向 k1/k2，共 14 个自由度，K 与 80 mm 尺寸固定。

标记四角按 ArUco 解码后的 canonical 顺序配对，坐标为 `[-.04,+.04,0],[+.04,+.04,0],[+.04,-.04,0],[-.04,-.04,0]`。不按屏幕 x/y 重新排序。

历史四角点求解器（也用于混合方法的训练内初始化）：初值包括固定 K/D 的 OpenCV calibrateCamera + Shah，以及小子集的 IPPE 双候选组合 + Shah/Li。最终目标在原始像素域，使用每角点 2×2 协方差白化和二维块 Huber IRLS。burst 协方差增加 0.15 px 噪声下限，不按重复帧数量无限缩小。

历史四角点优化使用右 SE(3) 扰动；信息检查按 1 mrad / 1 mm 归一化的数据雅可比计算。秩不足或多个相近代价的不同几何解不会标为成功。

默认混合求解直接使用内部交界点的实际亚像素测量与边缘直线交点，不把内部单应矩阵投影生成的四角作为新观测。内部点需至少 6 帧支持、每姿态至少 12 点；内部与外角点各半权重，每姿态总权重一致。使用逐坐标 1 px Huber，不对白化残差套用该像素阈值。图像质量筛选不使用机器人预测误差。边缘细化失败时显式记录并回退原 r3kit 外角点。

混合局部雅可比检查包含全部 14 个参数（X/Y 扰动尺度 .02，k1/k2 尺度 .1），并保守继承初值求解的退化/歧义状态。局部满秩不能证明全局唯一或真实毫米精度。每次保存独立目录、有效处理配置和原图哈希，不改采集配置。输出中 `camera_factory` 与拟合的 `camera` 分开，后者是 forward Brown 模型。训练内五个连续分组的每折初值也只用该折训练数据。历史测试数据已经多次被检查，报告按诊断验证解释。

## 时间和运动

手动示教阶段仅以 50 Hz 记录机器人状态，不实例化相机、不保存图像或相机内参。会话目录中的相机序列号来自配置，不代表已连接验证。选点只使用完整机器人轨迹的几何覆盖。旧版示教图像不参与选点或求解。

自动采集阶段才连接相机并保存实际流参数。机器人 50 Hz 读取线程与 RGB 采集分开，保留设备时间戳、主机单调时间和读取区间。设备时间域不直接相减。旧会话存在 `trajectory/camera.json` 时仍检查相机模型一致性；新会话无此文件，按计划的设备序列号和流配置检查，并在采集 manifest 中记录实际内参。

采样使用至少 1 秒静止窗口；检查关节峰峰变化（默认 0.0005 rad）、窗口关节变化/时长（0.003 rad/s）、法兰平移（0.2 mm）和旋转（0.05°）。原始 dq 保留供诊断，不以其单帧噪声判断静止。等待新 RGB 帧后采集，并持续检查实际变化。实际每帧关联前后反馈，求解使用有效观测对应的法兰均值，绝不使用运动目标替代实际反馈。

运动阶段仅保存原图、目标和实际反馈。全部点采集完、机器人停止且硬件连接关闭后，才离线检测图像；默认 `hybrid.extract` 在独立结果目录提取两类点，历史四角点入口继续使用 `filter_capture`。派生 `detections.json` 不覆盖原始 `frames.jsonl`；不合格点的所有原图仍保留。只用单帧质量通过的图像形成有效点，默认每点至少 6/10 帧通过。编码标记完整检测包含 ID 匹配、四角检测、画面边界余量和像素尺寸，不判断外部安装支架的完整性。

采样数量指计划访问点数，筛选后的有效数量可能更少。`filter_report.json` 记录全部点的接受/拒绝情况、逐帧失败原因和训练/测试计数。样本数量不足时不产生外参结果，不自动驱动机器人去未经计划的新位置。

回放选点后保留原先的关节路径顺序；RDP 简化最大关节偏离默认 0.001 rad，单段关节差不超过 0.025 rad。保留 home、末端及所有采样索引。仅在采样点和两端停车；相邻停车点间用五次 Hermite 曲线逐个经过中间规划路点，PCHIP 估计节点速度并以零节点加速度保证 C2 连续。Bezier 控制点凸包限制每段相对简化折线的关节偏离不超过另一个 0.001 rad；以导数控制点界缩放时间，限制指令速度、加速度、jerk。停车点速度与加速度为零。两项路径误差默认合计最多 0.002 rad/关节，这是指令几何误差界，不能换算为未测量的机械臂实际定位精度或碰撞保证。

通过 RDK `SendJointPosition` 以 50 Hz 连续发送目标位置和非零过渡速度，在实际轨迹末点发送零速度；RDK 内部运动生成器仍执行在线重规划。反馈线程检查状态新鲜度，发送循环检查关节跟踪误差、operational/fault 和超过 0.15 秒的调度间断，异常进入 finally Stop。Python 非实时循环不是硬件看门狗。该方法没有环境碰撞模型，依赖操作者示教的可通行区域和路径余量。旧会话缺少新增参数时使用同样默认值，并在新采集 manifest 的 effective_limits 中记录。

`replay_speed_scale` 在基准曲线生成后执行统一时间缩放，倍率 s 对应 q_new(t)=q_old(s·t)，位置路径不变，速度/加速度/jerk 分别乘 s、s²、s³；RDK 的速度与加速度限制同步缩放。2026-11-19 按用户要求将当前配置设为 3 倍；缺少此字段的旧会话仍按 1 倍执行。使用旧轨迹时需显式传入当前配置重新规划。初始端点对齐、停稳、图像采集以及故障/跟踪检查不加速；运行中的进程不热更新。

自动运动只在 `auto_calibrate.py --execute` 中发生。示教记录和设备检查不调用 Enable/SwitchMode/Stop；运动流程启用后，正常结束、异常和 Ctrl+C 都调用 Stop。fault 不自动清除；也不调用 PLAN-Home。SIGKILL/掉电不属于 Python finally 能处理的情况。

## 验证分组

选点计划阶段以固定种子封存 20% 的姿态为测试，最少 3 个测试点、10 个训练点。一个 burst 只属于一个样本；采集前通过末端位置/朝向最小间隔减少重复姿态。最终测试不能重新拟合逐帧标记位姿来降低重投影误差。

训练信息检查、留出像素误差和绝对物理精度是不同指标。参考点检查使用固定变换直接预测，没有在参考点上重新拟合外参。

独立参考文件格式（坐标米，参考误差毫米）：

```json
{
  "source": "独立测量方法和参考设备说明",
  "reference_uncertainty_mm": 0.2,
  "points_C_m": [[0,0,0.8],[0.1,0,0.8],[0,0.1,0.8]],
  "points_W_m": [[0.3,0,0.5],[0.4,0,0.5],[0.3,0.1,0.5]]
}
```

上述仅是格式示例，不能作为实际参考数据。物理通过条件为给定参考测点的最大误差加所填参考不确定度不超过 1 mm，且求解状态正常；结论范围仅限这些参考点。
